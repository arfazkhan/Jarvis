- **`get_equipment_status`**: Get the current status of a specific piece of BMS equipment including its operational state, data points, and active alarms.
- **`list_equipment`**: List all BMS equipment, optionally filtered by type, status, or location.
- **`get_equipment_health`**: Get detailed health analysis for specific equipment including health score, trending, and risk factors.
- **`get_point_history`**: Get historical values for a specific data point over a time period.
- **`get_equipment_specs`**: Search local technical manuals and specifications for a specific equipment or system. Use this to find hardware limits, manufacturer setpoints, or maintenance requirements.
- **`get_dashboard_overview`**: Get a summary overview of the building's current status including equipment counts, active alarms, energy metrics, and pending insights.
- **`get_active_alarms`**: Get all active alarms in the building, sorted by priority. Returns alarm details, severity, duration, and suggested actions.
- **`explain_alarm`**: Get detailed explanation and root cause analysis for a specific alarm, including related alarms and recommended actions.
- **`acknowledge_alarm`**: Acknowledge an alarm to indicate it has been seen and is being addressed.
- **`analyze_cascade`**: Find the root cause among multiple related alarms. When many alarms fire at once, this tool traces back to the originating equipment/failure. Returns the cascade tree showing cause-effect relationships.
- **`analyze_energy`**: Analyze energy consumption for a specific period. Detects anomalies, compares to baseline, and identifies waste patterns.
- **`get_energy_anomalies`**: Get detected energy waste patterns and anomalies with estimated savings potential.
- **`check_cost_impact`**: Calculate the financial cost (QAR) of a proposed temperature change. Shows current burn rate, new burn rate, and daily/monthly impact. Use before any setpoint change to warn users about costs.
- **`get_burn_rate`**: Get current building energy burn rate in QAR/hour. Shows projected daily and monthly costs.
- **`find_ghost_spaces`**: Scan all zones to find 'Ghost Operations' - rooms that are scheduled ON but detected as EMPTY based on CO2 levels. No hardware needed - uses existing BMS sensors. Returns potential savings.
- **`estimate_zone_occupancy`**: Estimate occupancy for a specific zone using virtual sensing (CO2, VAV position, lighting). Returns probability 0-1 and occupancy level.
- **`predict_maintenance`**: Get predictive maintenance analysis for equipment, including failure probability, remaining useful life, and recommendations.
- **`predict_remaining_life`**: Predict the Remaining Useful Life (RUL) for equipment. Returns health score, days until predicted failure, probability of failure at various timeframes, and degradation indicators. Use this to answer 'Will the chiller make it through summer?'
- **`verify_maintenance_work`**: Verify if maintenance work was actually done by comparing pre/post telemetry using physics. Catches 'Ghost Maintenance' where work is marked complete but no improvement measured.
- **`get_gsas_status`**: Get current GSAS (Global Sustainability Assessment System) compliance status including scores by category and recommendations.
- **`get_gsas_improvement_priorities`**: Get prioritized list of GSAS improvements ranked by impact on overall score. Shows the top 10 actions to take to improve the building's GSAS rating.
- **`generate_gord_report`**: Generate a GORD-compliant PDF report for GSAS Operations certification. This is the official report format required for submission to GORD (Gulf Organisation for Research & Development) for certification renewal. The report includes building scores, category breakdowns, BMS evidence, and signature blocks.
- **`get_advisory_recommendations`**: Get AI-generated, ML-ranked recommendations for resolving operational issues. Use this when an alarm is detected or an optimization opportunity is found. Returns multiple options ranked by predicted operator preference, including cost, risk, and benefit analysis.
- **`check_goals`**: Check for active proactive goals generated by the autonomous goal generator. Returns prioritized list of risks, waste reduction opportunities, and fleet optimization targets.
- **`generate_briefing`**: Generate a proactive operations briefing. Instead of the user hunting for issues, this provides: critical items needing attention, overnight anomalies, optimization wins, today's context (weather, events, tariffs), and prioritized recommendations.
- **`run_briefing`**: Generate an on-demand briefing (Daily Morning or Urgent Risk). Useful if the user asks 'What should I focus on today?' or 'Give me a briefing'.
- **`submit_feedback`**: Submit operator feedback for active learning. Use when the user corrects the system, explains a decision, or answers a specific question from the agent.
- **`get_trust_metrics`**: Get current advisor reliability metrics and system trust scores. Shows adoption rates, accuracy, and any detected model drift.
- **`forecast_energy`**: Forecast future energy demand using ML ensemble (Prophet + LightGBM). Provides hourly predictions with confidence intervals, considers Qatar-specific features like Ramadan, sandstorms, and extreme heat. Also detects anomalies in consumption patterns.
- **`detect_equipment_faults`**: Use ML autoencoder to detect equipment faults from sensor data. Applies physics-constrained VAE and ASHRAE RP-1312 fault rules. Returns fault type, severity, confidence, and recommended action.
- **`analyze_root_cause`**: Use Bayesian Network causal inference to find root cause of alarm cascades. Considers equipment topology, temporal sequence, and physical causality. Returns probability-weighted root causes and cascade prediction.
- **`simulate_with_uncertainty`**: Advanced what-if simulation using Gaussian Process regression and Monte Carlo. Provides uncertainty bounds & risk assessment for operational changes. Shows worst-case scenario and probability of negative outcomes.
- **`find_similar_skills`**: Use semantic embeddings to find relevant building skills from the Skillbook. Matches based on meaning not just keywords. Returns ranked list of applicable skills with similarity scores.
- **`benchmark_building_ml`**: Use ML clustering to identify building archetype and benchmark against similar buildings. Returns percentile rankings, archetype classification (e.g., 'Large Office Cooling-Dominated'), and improvement recommendations from similar high performers.
- **`think`**: Log internal reasoning, hypotheses, or a plan before taking action. Use this to clarify complex investigative steps.
- **`query_skillbook`**: Query the building's institutional memory (Skillbook). Returns learned knowledge about equipment quirks, patterns, past optimizations, and contractor notes. The Skillbook captures knowledge that would otherwise be lost when staff changes.
- **`add_to_skillbook`**: Record a new learning in the building's Skillbook. Use when discovering equipment quirks, confirming optimization results, or noting contractor performance. Skills gain confidence through verification.
- **`compare_to_fleet`**: Benchmark a building against the portfolio fleet. Shows percentile rankings, best-in-class areas, improvement opportunities with potential QAR savings, and best practices from top performers.
- **`simulate_change`**: Predict the impact of operational changes before implementing them. Answers questions like 'What if we raise setpoints by 1°C?' Returns energy impact (kWh, QAR), comfort impact, risk assessment, and fleet comparison.
- **`correlate_events`**: Find causal relationships across different systems (BMS, energy, access control, weather, calendar). Use when investigating 'why did energy spike?' or understanding multi-system incidents like 'fire drill during sandstorm'.
- **`task_boundary`**: Indicate the start of a task or update the current task. Use this as your VERY FIRST tool call when starting a new objective. Arguments: task_name, mode (PLANNING/EXECUTION/VERIFICATION), summary, status, predicted_task_size.
