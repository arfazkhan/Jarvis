# Advisory Detail — Product Designer Brief

**Feature**: The screen that proves an ARVIS recommendation is trustworthy. Agent trace, evidence ledger, verifier gates, counterfactual, operator actions.

**Audience**: Product designer, no ARVIS context.

---

## 30-second ARVIS primer

ARVIS is an AI advisor for commercial building operators. It produces **Advisories** — recommendations like "Schedule inspection of Chiller 4 within 48h." Every advisory is generated by multiple AI agents that vote, backed by evidence (sensor data, physics simulation, past incidents), and passes three automated checks (Claim, Faithfulness, Physics) before reaching the operator. Risk tiers: T1 (info), T2 (diagnostic), T3 (actionable). Same UI used in SIM/PILOT/PROD modes.

---

## Why this exists — **the trust screen**

Operators don't trust AI by default. This screen is where ARVIS earns trust by **showing its work**. Every claim is one click from its source. Every recommendation has visible evidence. The multi-agent vote is shown like doctors in a consult — not a black-box answer.

This is the screen that wins or loses a sales demo.

---

## Users

- **Operator (Bilal)** — decides: approve, reject, snooze
- **Engineer / auditor** — debugs: why did ARVIS say this?
- **Facility manager (Ahmed)** — reviews for T3 approval
- **Sales / customer** — sees the moats made visible

---

## Scope

**In**:
- Header (risk tier, summary, target equipment)
- Recommendation block + confidence
- Why (plain-English explainer)
- Counterfactual (with/without action)
- Agent trace (vote timeline)
- Evidence ledger (clickable chips → sources)
- Verifier gates (pass/fail badges)
- Operator action bar (approve/reject/snooze)
- Recent operator actions context (when relevant)

**Out**:
- Equipment trend chart (Equipment Detail owns)
- Search past advisories (Audit & Replay owns)
- Bulk actions (Live View owns the feed)

## Component details

### Header

- Risk tier chip: T1 (blue) / T2 (amber) / T3 (red), with text label
- Summary: one sentence, ≤120 chars
- Targeting chips for equipment
- Created timestamp (relative + absolute on hover)
- Recommended action window
- Shadow chip if PILOT-shadow

### Recommendation block

- Action verb forward ("Schedule inspection of...")
- Predicted outcome: savings, MTBF delta, failure prob delta
- Confidence bar (0-100%)
- For T3 (actionable): add "This will write to BMS" warning chip

### Why

- 2-3 sentences plain English. Not GSAS-spec or engineering jargon.
- Bullet list of key evidence points
- Each bullet is a clickable chip → scrolls to that evidence in ledger

### Counterfactual

- Two side-by-side cards
- Numbers, not words (operator wants the magnitude)
- Color: "With action" subtle green, "Without action" subtle red
- Time horizon shown (default 30d, configurable)

### Verifier gates

- 3 large pass/fail badges visible at all times
- Each clickable → expands detail
- If any failed but advisory still shipped: red banner "Shipped with caveat — Faithfulness regen-failed"
- Abstention indicator: shows if abstention gate fired, with the 4 signals (data_coverage, truth_score, ml_fallback_ratio, max_drift)

### Agent Trace

- Vertical timeline (chronological order)
- Each row: agent icon + name + verdict chip (APPROVE green / APPROVE_WITH_CONDITION amber / VETO red / ABSTAIN gray) + confidence + reasoning summary
- ABSTAIN agents shown muted (they didn't poison the vote, just sat it out)
- Expandable per-agent for full reasoning + tools called

### Evidence Ledger

- Chip cloud or table view (toggle)
- Each chip: source icon, brief value, click → drill into source
  - Historian → modal with chart
  - Physics simulator → modal with simulator inputs/outputs
  - Memory → navigate to memory entry detail
  - ML model → modal with model + lineage
  - Operator input → modal with audit log
- Filter by source type
- Search within ledger (P1)

### Recent operator actions (conditional)

- Renders only if `operator_context.attributed_to_operator === true`
- "Bilal changed CH-4 chilled water setpoint 7°C → 6.5°C at 14:28 (4 min ago)"
- Helps operator realize the "fault" is their own change

### Operator action bar

- Sticky bottom
- Buttons: Approve (primary), Reject (secondary), Snooze (tertiary dropdown: 1h/4h/shift/24h/custom)
- T3 actions: extra confirm modal
- T3 without permission: button disabled, "Requires Facility Manager" tooltip + "Escalate" button

---

## States

- **Loading**: skeleton honors final layout shape
- **Pending**: default state described above
- **Approved**: header shows "Approved by Bilal at 14:35, comment: 'Scheduled Sunday'", action bar replaced by reopen / view-task links
- **Rejected**: header shows "Rejected by Bilal at 14:36, reason: false_positive, freetext: 'Ambient was 48°C'"
- **Snoozed**: header shows "Snoozed until 18:00"
- **Auto-withdrawn**: header shows "Withdrawn by ARVIS — root condition resolved"
- **Replay mode** (from Audit & Replay): frozen timestamp banner at top, all live indicators show "as of T"
- **Verifier failed but shipped**: red banner above header, gates panel expanded by default

## Flows

### Flow A — T2 happy path

1. Operator opens from Live View feed
2. Reads header + recommendation
3. Glances counterfactual (kWh savings magnitude)
4. Skips agent trace + evidence ledger (trust verifier gates green)
5. Clicks Approve → optional comment → toast

Time: <30 seconds.

### Flow B — Skeptical engineer audits

1. Engineer opens (from Audit Replay or share link)
2. Expands Why
3. Expands Agent Trace — checks who voted what
4. Expands Evidence Ledger — clicks each chip to verify source
5. Reads Verifier Gates detail
6. Decides: ARVIS got it right (or files internal bug)

Time: 2-5 minutes.

### Flow C — T3 actionable

1. Facility manager opens T3 advisory
2. Sees "This will write to BMS" warning chip
3. Reviews carefully
4. Clicks Approve → confirm modal: "ARVIS will write setpoint CH-4/CWST = 28°C. Confirm? [Cancel] [Yes, write]"
5. Confirms → toast + audit log entry

### Flow D — Operator-attributed anomaly

1. Operator opens advisory
2. Sees Recent Operator Actions block prominently
3. Realizes the "fault" is just their setpoint change
4. Clicks Reject with reason "operator_caused"
5. Advisory dismissed

## Design principles

1. **The screen earns trust by showing work**. Verifier gates always visible. Evidence always one click from source.
2. **Operator can decide in <30 sec without expanding anything**. Engineer can audit in <2 min by expanding everything. Both reads work.
3. **Multi-agent vote is the differentiator**. Make it visual, not buried.
4. **Counterfactual is the value proof**. With/without numbers, not words.
5. **Confirm modals only for irreversible actions** (T3 writeback). Approve/reject/snooze for T1/T2 are one-click.
6. **Operator actions block surfaces when relevant**, hides when not. Don't show empty.

---

## Edge cases

- Advisory with 0 evidence (impossible per engine — but guard for it): show "Evidence ledger unavailable" with subtle warning
- Agent voted VETO: shown in red, full reasoning expanded by default — this is the dissent
- Counterfactual unavailable (no physics simulator): show "Counterfactual not computed" with reason
- 10+ agents voted: trace collapsible, default shows top 5 by confidence
- Same advisory opened by two operators: live update — if one approves, the other sees the state change immediately
- Verifier failed + shipped + corrected: show original + corrected side-by-side (diff view) in expanded gate detail

---

## Open questions

1. **Verifier gate copy**: technical names (Claim/Faithfulness/Physics) vs plain language (Facts checked / Logic checked / Physics checked)? Recommendation: plain language with technical name on hover.
2. **Evidence chip density**: chip cloud (flexible) vs table (sortable, structured)? Default chip cloud, toggle for table.
3. **Approve confirm scope**: T1 no confirm, T2 light confirm (comment optional), T3 modal confirm. Confirm aligned with risk?
4. **Trace timeline orientation**: vertical (current proposal) vs horizontal (swimlane)? With 8+ agents, vertical wins.
5. **Recent actions lookback window**: 5 min (current) or configurable?

## Success criteria

- Operator decides <30s for T2, <2min for T3
- Engineer audits in <2min
- Customer in demo says "but how do I know it's not making this up?" → demo person clicks one chip → customer satisfied
- Advisory approve rate ≥70% (pilot week 2 target)
